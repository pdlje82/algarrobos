# Funding Navigator changes

## 2026-11-01 — remember exploration programme and working route

- Programme and working-route choices now belong to each exploration's optional,
  versioned navigation state and participate in autosave, reload, saved
  alternatives, duplication and export/import. Clearing a route keeps its programme.
- Added explicit validation of saved identities and membership. Failed saves retain
  the chosen focus and offer the existing retry; navigation does not alter scoring
  answers, shortlisted options or historical records.
- Verified 82 funding Python tests, 100 frontend tests, the production build and
  isolated browser checks for focus persistence, programme navigation and saved
  exploration resume, including distinct alternatives and failed-save retry.

## 2026-11-01 — shared delivery plans, scoring completion and pinned headers

- Added route-aware delivery planning to shared concepts, with unresolved defaults,
  explicit review of existing values, combined monitoring methods and activity links.
  Topic fields participate in two-way reconciliation and deterministic briefs.
- Added reviewed execution previews/apply, primary-method adaptation and applied
  snapshots. Route 3.5 never silently uses route-3.4 simulator financing.
- Moved pending scoring confirmations directly above their dropdowns, with visible
  proposed values, amber/red feedback, explicit atomic changes and preserved notes.
- Added selection-library version 2 for cap-aware completion. Frozen version-1
  calculations and saved assessments remain supported; adoption is explicitly reviewed.
- Pinned the four graph headers independently of vertical node scrolling, while
  retaining horizontal alignment and responsive column controls.
- Verified with 268 Python tests, 98 frontend tests, the production build and
  eight isolated browser workflows. Coverage includes both delivery routes,
  failed-library/write retries, explicit execution financing, multi-method
  monitoring, source focus, pinned expanded/compact headers and mobile themes.

## 2026-11-01 — project concepts and individual sub-node editors

- Added one editor per scoring sub-node across all five AL20 routes, sibling
  navigation, independent annotations, retained shared context and explicit
  atomic review for related answer changes. Moved group reset controls outside
  item editors; calculations and point definitions are unchanged.
- Added separate 3.4/3.5 concepts, explicit starter inclusion, manual activities,
  reusable need/criterion links, evidence tasks and gap review. All 95 bindings
  have validated, source-cited instructions in a versioned central library.
- Added the same deterministic brief, Markdown download and print view to both
  workspaces. Unknown details and NPL15/NPL18 mapping questions remain visible;
  activities and notes cannot award points.
- Added reviewed initial transfer and three-way updates to both linked copies,
  stable identities/baselines, explicit conflicts/removals, revision checks,
  idempotent requests, atomic writes, visible failures and retained drafts.
  Planning content remains independent of simulator quantities and financing.
- Added validated optional concept/annotation fields without upgrading old
  saves or rewriting adopted history; export/import retains the new content.
- Verified with 257 Python tests, 94 frontend tests, the production build and
  six isolated browser workflows: concepts, scoring, guidance, EDL, statistics
  and resume. Checks include delayed transfer responses with newer edits,
  stale comparisons, write failures, retry, source-viewer focus and mobile use.
  The older general `funding.cjs` browser script still targets the retired
  “Answer questions” control and needs a separate programme-graph update;
  it is not included in those six passing workflows.
